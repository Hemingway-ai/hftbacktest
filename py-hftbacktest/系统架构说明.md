# py-hftbacktest 子目录系统架构说明

> 参考根目录《系统架构分析.md》整理，范围仅覆盖 `py-hftbacktest/` 子目录。

## 1. 范围与目标

- 范围：`py-hftbacktest/` 目录下全部文件（含源码、测试、构建产物与缓存文件）。
- 目标：给出逐文件目录树说明，并总结 Python 绑定子项目整体架构。

## 2. 整体架构说明

### 2.1 模块定位

`py-hftbacktest` 是 `hftbacktest` 的 Python 绑定与数据工具子项目，核心职责：

1. 通过 `pyo3 + maturin` 将 Rust 回测/实盘引擎暴露给 Python。
2. 通过 `ctypes + numba jitclass` 构建可在 `njit` 中直接调用的高性能 Python 接口。
3. 提供多交易所历史数据转换、事件校验、延迟构造与统计分析工具。

### 2.2 代码分层

1. **Rust 扩展层（`src/*.rs`）**
- `src/lib.rs`：PyO3 模块入口 `_hftbacktest`、`BacktestAsset/LiveInstrument` 构建器、回测/实盘构建函数。
- `src/backtest.rs`：Backtest FFI 导出（行情推进、下单、订单查询、状态读取）。
- `src/live.rs`：LiveBot FFI 导出（实盘侧同类接口）。
- `src/depth.rs`：深度簿查询与快照导出 FFI。
- `src/order.rs`：订单字典迭代与查询 FFI。
- `src/fuse.rs`：深度融合器 FFI（`FusedHashMapMarketDepth` 封装）。

2. **Python 绑定层（`hftbacktest/*.py`）**
- `__init__.py`：高层 API 入口，封装 `BacktestAsset` 和两类 MarketDepth Backtest 构造器。
- `binding.py`：底层 `ctypes` 函数签名 + `numba` 友好的 jitclass 包装。
- `types.py/order.py/state.py/recorder.py`：事件/订单/状态 dtype 与对象接口。
- `intrinsic.py`：numba intrinsic（指针和值转换）桥接。

3. **数据工具与分析层（`hftbacktest/data`、`hftbacktest/stats`）**
- `data/utils/*.py`：Binance/Bybit/Hyperliquid/MEXC/Tardis/DataBento 数据转换与快照差分处理。
- `data/validation.py`：事件顺序与延迟修正。
- `stats/*.py`：指标计算、分组统计与绘图。

4. **打包与测试层**
- `pyproject.toml`：Python 包元信息与 maturin 构建配置。
- `Cargo.toml`：Rust cdylib 绑定配置。
- `tests/test_hftbacktest.py`：基础端到端调用样例测试。

### 2.3 关键数据流

1. `BacktestAsset`（Python）配置参数 -> `build_hashmap_backtest/build_roivec_backtest`（Rust）组装 `Backtest`。
2. Python `binding.py` 通过 `ctypes` 调 Rust 导出函数，再封装为 `numba jitclass` 可用接口。
3. `data/utils/*` 将外部原始行情转为统一 `event_dtype`，回测引擎直接消费。
4. `Recorder` 记录状态序列，`stats` 模块产出收益、回撤、Sharpe 等指标。

## 4. 逐文件映射表（完整相对路径）

- `py-hftbacktest/hftbacktest/__init__.py`：Python 高层入口，封装资产配置与 Backtest 构建函数。
- `py-hftbacktest/hftbacktest/_hftbacktest.cpython-312-darwin.so`：本地编译的 Python 扩展动态库。
- `py-hftbacktest/hftbacktest/binding.py`：ctypes 函数绑定、numba jitclass 适配、Backtest/Depth/Order 桥接。

- `py-hftbacktest/hftbacktest/data/utils/__init__.py`：utils 包入口文件（当前为空实现）。
