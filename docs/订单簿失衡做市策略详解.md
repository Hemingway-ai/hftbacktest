# 基于订单簿失衡的做市策略详解

## 一、策略概述

本策略是一种基于**订单簿失衡(Order Book Imbalance, OBI)**的高频做市策略。订单簿失衡是一种重要的市场微观结构指标，通过分析买卖盘的深度差异来预测短期价格走势。

### 核心思想
- 当买盘深度大于卖盘深度时，表明市场买方力量较强，价格可能上涨
- 当卖盘深度大于买盘深度时，表明市场卖方力量较强，价格可能下跌
- 策略根据失衡程度调整报价，在失衡方向上更激进地报价

---

## 二、理论基础

### 2.1 静态订单簿失衡 (Static Order Book Imbalance)

$$
Static\ Order\ Book\ Imbalance = \frac{\sum_{i}^{N}Q_{bid}^{i} - \sum_{i}^{N}Q_{ask}^{i}}{\sum_{i}^{N}Q_{bid}^{i} + \sum_{i}^{N}Q_{ask}^{i}}
$$

其中：
- $Q_{bid}^{i}$ 表示第 i 档买盘数量
- $Q_{ask}^{i}$ 表示第 i 档卖盘数量
- N 表示观察的档位深度

### 2.2 标准化订单簿失衡

本策略使用的是**标准化订单簿失衡**：

$$
Standardized\ Order\ Book\ Imbalance = standardize(\sum_{i}^{N}Q_{bid}^{i} - \sum_{i}^{N}Q_{ask}^{i})
$$

标准化处理使得失衡指标具有可比性，便于设置阈值。

### 2.3 其他相关指标

#### VAMP (Volume Adjusted Mid Price)
$$
VAMP_{bbo} = \frac{P_{best\ bid} \times Q_{best\ ask} + P_{best\ ask} \times Q_{best\ bid}}{Q_{best\ bid} + Q_{best\ ask}}
$$

#### 加权深度订单簿价格
$$
Weighted-Depth\ Order\ Book\ Price = \frac{\sum_{i}^{N}P_{bid}^{i} \times Q_{bid}^{i} + \sum_{i}^{N}P_{ask}^{i} \times Q_{ask}^{i}}{\sum_{i}^{N}Q_{bid}^{i} + \sum_{i}^{N}Q_{ask}^{i}}
$$

### 3.2 策略主函数 `obi_mm`

```python
@njit
def obi_mm(
    hbt,                    # 回测引擎实例
    stat,                   # 统计记录器
    half_spread,            # 半价差（基点）
    skew,                   # 仓位偏斜系数
    c1,                     # alpha系数
    looking_depth,          # 观察深度（百分比）
    interval,               # 更新间隔（纳秒）
    window,                 # 标准化窗口大小
    order_qty_dollar,       # 订单金额（美元）
    max_position_dollar,    # 最大持仓金额（美元）
    grid_num,               # 网格订单数量
    grid_interval,          # 网格间隔
    roi_lb,                 # ROI下界
    roi_ub                  # ROI上界
):
```

**参数说明：**
| 参数 | 类型 | 含义 |
|------|------|------|
| `half_spread` | float | 报价与公平价格的半价差，控制买卖价差 |
| `skew` | float | 仓位风险厌恶系数，用于调整报价以控制库存 |
| `c1` | float | alpha信号强度系数，决定失衡信号对报价的影响程度 |
| `looking_depth` | float | 观察深度（如0.025表示2.5%价格范围内的深度） |
| `interval` | int | 策略更新频率（纳秒），1_000_000_000 = 1秒 |
| `window` | int | 标准化的时间窗口大小 |
| `order_qty_dollar` | float | 每笔订单的名义价值 |
| `max_position_dollar` | float | 最大持仓限制 |
| `grid_num` | int | 网格订单数量 |
| `grid_interval` | float | 网格订单价格间隔 |

### 3.3 初始化部分

```python
asset_no = 0
imbalance_timeseries = np.full(30_000_000, np.nan, np.float64)

tick_size = hbt.depth(0).tick_size
lot_size = hbt.depth(0).lot_size

t = 0
roi_lb_tick = int(round(roi_lb / tick_size))
roi_ub_tick = int(round(roi_ub / tick_size))
```

**逐行解释：**
- `asset_no = 0`: 资产编号，多资产回测时用于区分
- `imbalance_timeseries`: 预分配3000万个元素的数组存储失衡时间序列，初始化为NaN
- `tick_size`: 最小价格变动单位
- `lot_size`: 最小交易数量单位
- `t`: 时间步计数器
- `roi_lb_tick/roi_ub_tick`: 将ROI边界转换为tick单位

### 3.4 主循环

```python
while hbt.elapse(interval) == 0:
    hbt.clear_inactive_orders(asset_no)
    
    depth = hbt.depth(asset_no)
    position = hbt.position(asset_no)
    orders = hbt.orders(asset_no)

    best_bid = depth.best_bid
    best_ask = depth.best_ask
    
    mid_price = (best_bid + best_ask) / 2.0
```

**逐行解释：**
- `hbt.elapse(interval)`: 推进时间interval纳秒，返回0表示数据未耗尽
- `hbt.clear_inactive_orders()`: 清理已失效的订单
- `depth`: 获取当前市场深度数据
- `position`: 获取当前持仓
- `orders`: 获取当前活跃订单
- `best_bid/best_ask`: 最优买/卖价
- `mid_price`: 中间价

---

### 3.5 计算订单簿失衡

```python
sum_ask_qty = 0.0
from_tick = max(depth.best_ask_tick, roi_lb_tick)
upto_tick = min(int(np.floor(mid_price * (1 + looking_depth) / tick_size)), roi_ub_tick)
for price_tick in range(from_tick, upto_tick):
    sum_ask_qty += depth.ask_depth[price_tick - roi_lb_tick]
        
sum_bid_qty = 0.0
from_tick = min(depth.best_bid_tick, roi_ub_tick)
upto_tick = max(int(np.ceil(mid_price * (1 - looking_depth) / tick_size)), roi_lb_tick)
for price_tick in range(from_tick, upto_tick, -1):
    sum_bid_qty += depth.bid_depth[price_tick - roi_lb_tick]

imbalance_timeseries[t] = sum_bid_qty - sum_ask_qty
```

**逐行解释：**
- **卖盘深度计算**：
  - `from_tick`: 从最优卖价开始
  - `upto_tick`: 计算到 `mid_price * (1 + looking_depth)` 处
  - 累加该范围内的卖盘数量
  
- **买盘深度计算**：
  - `from_tick`: 从最优买价开始
  - `upto_tick`: 计算到 `mid_price * (1 - looking_depth)` 处
  - 累加该范围内的买盘数量

- `imbalance_timeseries[t]`: 存储当前时刻的失衡值（买盘总量 - 卖盘总量）

---

### 3.6 标准化处理

```python
m = np.nanmean(imbalance_timeseries[max(0, t + 1 - window):t + 1])
s = np.nanstd(imbalance_timeseries[max(0, t + 1 - window):t + 1]) 
alpha = np.divide(imbalance_timeseries[t] - m, s)
```

**逐行解释：**
- `m`: 计算过去window个时间步的失衡均值
- `s`: 计算过去window个时间步的失衡标准差
- `alpha`: 标准化后的失衡值（Z-score）

**数学含义：**
$$\alpha = \frac{OBI_t - \mu_{window}}{\sigma_{window}}$$

---

### 3.7 计算报价价格

```python
order_qty = max(round((order_qty_dollar / mid_price) / lot_size) * lot_size, lot_size)
fair_price = mid_price + c1 * alpha

normalized_position = position / order_qty

reservation_price = fair_price - skew * normalized_position

bid_price = min(np.round(reservation_price - half_spread), best_bid)
ask_price = max(np.round(reservation_price + half_spread), best_ask)

bid_price = np.floor(bid_price / tick_size) * tick_size
ask_price = np.ceil(ask_price / tick_size) * tick_size
```

**逐行解释：**
- `order_qty`: 将订单金额转换为实际数量，并取整到lot_size的整数倍
- `fair_price`: 公平价格 = 中间价 + alpha信号调整
  - 正alpha（买盘强）→ 公平价格上移
  - 负alpha（卖盘强）→ 公平价格下移
- `normalized_position`: 标准化持仓（以订单数量为单位）
- `reservation_price`: 预留价格 = 公平价格 - 仓位惩罚
  - 正持仓 → 降低预留价格，鼓励卖出
  - 负持仓 → 提高预留价格，鼓励买入
- `bid_price`: 买入报价 = 预留价格 - 半价差，不超过最优买价
- `ask_price`: 卖出报价 = 预留价格 + 半价差，不低于最优卖价
- 最后两行：将价格对齐到tick_size

**关键公式：**
$$P_{reservation} = P_{fair} - \lambda \cdot \frac{Q_{position}}{Q_{order}}$$

其中 $\lambda$ 是skew参数，用于库存风险管理。

---

### 3.8 创建订单网格

```python
new_bid_orders = Dict.empty(np.uint64, np.float64)
if position * mid_price < max_position_dollar and np.isfinite(bid_price):
    for i in range(grid_num):
        bid_price_tick = round(bid_price / tick_size)
        new_bid_orders[uint64(bid_price_tick)] = bid_price
        bid_price -= grid_interval

new_ask_orders = Dict.empty(np.uint64, np.float64)
if position * mid_price > -max_position_dollar and np.isfinite(ask_price):
    for i in range(grid_num):
        ask_price_tick = round(ask_price / tick_size)
        new_ask_orders[uint64(ask_price_tick)] = ask_price
        ask_price += grid_interval
```

**逐行解释：**
- 创建空的订单字典，key为价格tick（用作订单ID），value为价格
- **买入订单**：
  - 检查持仓是否超过上限
  - 检查买入价格是否有效
  - 创建grid_num个买入订单，价格递减grid_interval
- **卖出订单**：
  - 检查持仓是否超过下限
  - 检查卖出价格是否有效
  - 创建grid_num个卖出订单，价格递增grid_interval

---

### 3.9 订单管理

```python
order_values = orders.values();
while order_values.has_next():
    order = order_values.get()
    if order.cancellable:
        if (
            (order.side == BUY and order.order_id not in new_bid_orders)
            or (order.side == SELL and order.order_id not in new_ask_orders)
        ):
            hbt.cancel(asset_no, order.order_id, False)
            
for order_id, order_price in new_bid_orders.items():
    if order_id not in orders:
        hbt.submit_buy_order(asset_no, order_id, order_price, order_qty, GTX, LIMIT, False)
        
for order_id, order_price in new_ask_orders.items():
    if order_id not in orders:
        hbt.submit_sell_order(asset_no, order_id, order_price, order_qty, GTX, LIMIT, False)
```

**逐行解释：**
- **取消旧订单**：
  - 遍历当前所有活跃订单
  - 如果订单不在新的订单网格中，则取消
- **提交新订单**：
  - 遍历新的订单网格
  - 如果该价格没有活跃订单，则提交新订单
  - `GTX`: Good-Till-Crossing，只做Maker
  - `LIMIT`: 限价单

## 六、策略优化建议

### 6.1 参数优化方向

1. **half_spread**: 调整价差以适应市场波动
2. **skew**: 调整库存风险控制力度
3. **c1**: 调整alpha信号的影响权重
4. **looking_depth**: 调整观察深度
5. **window**: 调整标准化窗口大小

### 6.2 策略改进方向

1. **多因子组合**: 结合其他微观结构指标
2. **动态参数**: 根据市场状态调整参数
3. **风控增强**: 添加止损、止盈逻辑
4. **执行优化**: 优化订单提交策略
