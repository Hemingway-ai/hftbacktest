# 延迟模型与队列模型详解

## 一、概述

延迟模型和队列模型是 HftBacktest 实现**真实回测**的核心组件。它们模拟了真实交易环境中两个最关键的因素：

1. **延迟模型 (LatencyModel)**：模拟订单从提交到确认的时间延迟
2. **队列模型 (QueueModel)**：模拟限价单在订单簿中的排队位置对成交概率的影响

---

## 二、延迟模型 (LatencyModel)

### 2.1 为什么需要延迟模型？

在真实交易中，订单不是 instant 执行的：

```
真实交易时间线:
t0: 策略决定下单
    │
    ├── entry_latency (网络传输 + 交易所处理)
    │
t1: 订单到达交易所，进入订单簿
    │
    ├── 撮合等待 (可能被成交)
    │
t2: 订单响应返回策略
    │
    ├── resp_latency (网络传输)
    │
t3: 策略收到确认
```

如果不模拟延迟，回测会产生**未来信息偏差**——策略可以"预知"将要发生的事件。

### 2.2 ConstantLatency — 固定延迟模型

最简单的延迟模型，使用固定值：

```python
# Python 配置
asset = (
    BacktestAsset()
    .constant_order_latency(
        entry_latency=100_000,   # 100 微秒提交延迟
        resp_latency=100_000     # 100 微秒响应延迟
    )
)
```

```rust
// Rust 实现
pub struct ConstantLatency {
    pub entry: i64,   // 纳秒
    pub resp: i64,    // 纳秒
}

impl LatencyModel for ConstantLatency {
    fn entry_latency(&self, _current_ts: i64) -> i64 {
        self.entry
    }
    fn resp_latency(&self, _current_ts: i64) -> i64 {
        self.resp
    }
}
```

**适用场景**：
- 初步策略验证
- 对延迟不敏感的策略
- 缺少真实延迟数据时

### 2.3 IntpOrderLatency — 插值延迟模型

基于历史延迟数据的插值模型，更真实地模拟实际延迟：

```python
# 加载延迟数据
latency_data = np.load('order_latency_btcusdt.npz')['data']

# Python 配置
asset = (
    BacktestAsset()
    .intp_order_latency(
        data=latency_data,
        latency_offset=0  # 可选：跨交易所时的额外偏移
    )
)
```

```rust
// Rust 实现
pub struct IntpOrderLatency {
    data: Vec<LatencyRecord>,  // 历史延迟记录
    offset: i64,               // 延迟偏移
}

struct LatencyRecord {
    req_ts: i64,    // 请求时间戳
    exch_ts: i64,   // 交易所时间戳
    resp_ts: i64,   // 响应时间戳
}
```

**工作原理**：
1. 根据当前时间戳在历史数据中找到最近的记录
2. 线性插值计算当前的 entry_latency 和 resp_latency
3. 加上可选的 latency_offset

**延迟数据格式**：
```python
latency_dtype = np.dtype([
    ('req_ts', 'i8'),     # 策略提交时间戳
    ('exch_ts', 'i8'),    # 交易所接收时间戳
    ('resp_ts', 'i8'),    # 策略收到响应时间戳
])
```

### 2.4 latency_offset — 跨交易所偏移

当数据采集地点与策略运行地点不同时，需要添加额外延迟：

```python
# 场景：数据从美国采集，策略在亚洲运行
# 物理距离导致的额外网络延迟约 50-100ms

asset = (
    BacktestAsset()
    .intp_order_latency(
        data=latency_data,
        latency_offset=50_000_000  # 50ms 额外延迟
    )
)
```

### 2.5 延迟对策略的影响

| 延迟水平 | 影响 |
|----------|------|
| < 1ms | 可以捕捉短暂的价格偏离 |
| 1-10ms | 适合中频做市策略 |
| 10-100ms | 适合低频策略，需要更大的价差 |
| > 100ms | 不适合高频策略 |

**关键指标**：`Impact of Order Latency.ipynb` 教程展示了延迟对策略 PnL 的量化影响。

## 三、队列模型 (QueueModel)

### 3.1 为什么需要队列模型？

限价单提交后不是立即成交的，它需要在订单簿中排队：

```
订单簿 (价格 100.0):
├── 订单 A (先到) ── 位置 1 ── 优先成交
├── 订单 B (你的订单) ── 位置 2
├── 订单 C ── 位置 3
└── ...

当有卖单以 100.0 成交时:
- 需要先消化订单 A 的数量
- 然后才轮到你的订单 B
- 如果卖单数量不够，你的订单可能部分成交或不成交
```

### 3.2 ProbQueueModel — 概率排队模型

基于队列位置计算成交概率：

```python
asset = (
    BacktestAsset()
    .power_prob_queue_model(n=3)  # 幂次概率模型
)
```

```rust
pub struct ProbQueueModel<F: ProbQueueFunc> {
    func: F,
}

pub trait ProbQueueFunc {
    fn probability(&self, queue_position: f64, queue_size: f64) -> f64;
}
```

**成交概率公式**：

```
P(fill) = 1 - (position / size)^n
```

其中：
- `position`: 你的订单在队列中的位置
- `size`: 队列总大小
- `n`: 幂次参数

**示例**：
```
队列大小 = 100
你的位置 = 10
n = 3

P(fill) = 1 - (10/100)^3 = 1 - 0.001 = 0.999 (99.9%)
```

### 3.3 概率函数变体

#### PowerProbQueueFunc

```python
.power_prob_queue_model(n=3)   # P = 1 - (pos/size)^n
.power_prob_queue_model2(n=3)  # 变体 2
.power_prob_queue_model3(n=3)  # 变体 3
```

**参数 n 的影响**：
- n 越大，队列位置越重要
- n=1: 线性关系
- n=2: 平方关系
- n=3: 立方关系 (推荐)

#### LogProbQueueFunc

```python
.log_prob_queue_model()    # P = 1 - log(pos)/log(size)
.log_prob_queue_model2()   # 变体 2
```

### 3.4 RiskAdverseQueueModel — 风险厌恶模型

更保守的成交概率估计：

```python
asset = (
    BacktestAsset()
    .risk_adverse_queue_model()
)
```

**特点**：
- 低估成交概率
- 适合需要严格风控的策略
- 避免过度乐观的回测结果

### 3.5 L3FIFOQueueModel — L3 FIFO 模型

基于 L3 (Market-By-Order) 数据的精确 FIFO 排队：

```python
asset = (
    BacktestAsset()
    .l3_fifo_queue_model()
)
```

**要求**：
- 需要 L3 级别的市场数据
- 精确跟踪每个订单的排队位置
- 最真实的模拟，但数据获取成本高

### 3.6 队列模型对比

| 模型 | 精度 | 数据要求 | 适用场景 |
|------|------|----------|----------|
| `risk_adverse_queue_model` | 低 (保守) | L2 | 风控严格策略 |
| `log_prob_queue_model2` | 中 | L2 | 通用场景 (默认) |
| `power_prob_queue_model(3)` | 中-高 | L2 | 需要精确模拟 |
| `l3_fifo_queue_model` | 高 | L3 | 最真实模拟 |

## 四、模型配置最佳实践

### 4.1 做市策略推荐配置

```python
asset = (
    BacktestAsset()
    .data(['market_data.npz'])
    .initial_snapshot('snapshot.npz')
    .linear_asset(1.0)
    # 使用历史延迟数据
    .intp_order_latency(latency_data)
    # 使用概率排队模型
    .power_prob_queue_model(3)
    # 做市策略通常不允许部分成交
    .no_partial_fill_exchange()
    # Maker 返点 + Taker 费率
    .trading_value_fee_model(-0.00005, 0.0007)
    .tick_size(0.1)
    .lot_size(0.001)
    .roi_lb(0)
    .roi_ub(3000)
)
```

### 4.2 趋势策略推荐配置

```python
asset = (
    BacktestAsset()
    .data(['market_data.npz'])
    .linear_asset(1.0)
    # 趋势策略对延迟更敏感
    .intp_order_latency(latency_data, latency_offset=10_000_000)
    # 风险厌恶模型
    .risk_adverse_queue_model()
    # 允许部分成交
    .partial_fill_exchange()
    # 纯 Taker
    .trading_value_fee_model(0, 0.0007)
    .tick_size(0.1)
    .lot_size(0.001)
)
```

### 4.3 参数调优建议

| 参数 | 调优方向 |
|------|----------|
| `latency_offset` | 根据实际服务器位置调整 |
| `n` (power_prob) | 从 2 开始，根据回测结果调整 |
| `maker_fee` / `taker_fee` | 使用交易所最新费率 |

## 五、模型实现原理

### 5.1 延迟模型在回测中的应用

```
Backtest 引擎事件循环:
1. Reader 读取市场数据事件 (时间戳 t)
2. Local 处理器接收数据，更新订单簿
3. 策略代码运行，产生订单请求
4. OrderBus 记录订单，设置:
   - delivery_ts = current_ts + entry_latency
5. EventSet 调度到 delivery_ts 时处理
6. Exchange 处理器接收订单，模拟撮合
7. OrderBus 记录响应，设置:
   - delivery_ts = current_ts + resp_latency
8. EventSet 调度到 delivery_ts 时处理
9. Local 处理器接收响应，更新订单状态
```

### 5.2 队列模型在成交判断中的应用

```
Exchange 处理器收到市场数据更新:
1. 检查所有挂单
2. 对于每个挂单:
   a. 计算队列位置 (q)
   b. 计算队列大小 (queue_size)
   c. 计算成交概率: P = queue_model.fill_probability(q, queue_size, traded_qty)
   d. 生成随机数 r
   e. 如果 r < P，订单成交
3. 更新订单状态
4. 发送订单响应
```

## 六、常见问题

### Q1: 回测结果太乐观怎么办？

- 使用 `risk_adverse_queue_model` 替代 `power_prob_queue_model`
- 增加 `latency_offset` 模拟更大的延迟
- 检查手续费设置是否准确

### Q2: 如何验证延迟模型的准确性？

- 比较回测中的 `order_latency()` 返回值与真实数据
- 使用 `logging_order_latency.rs` 示例记录实盘延迟
- 参考 `Impact of Order Latency.ipynb` 教程

### Q3: L3 数据如何获取？

- 部分交易所提供 L3 WebSocket API
- Tardis 和 Databento 提供 L3 历史数据
- 数据量大，存储成本高

### Q4: 队列模型参数如何选择？

| 场景 | 推荐模型 | 推荐参数 |
|------|----------|----------|
| 初步验证 | `log_prob_queue_model2` | 默认 |
| 做市策略 | `power_prob_queue_model` | n=3 |
| 保守估计 | `risk_adverse_queue_model` | 默认 |
| 精确模拟 | `l3_fifo_queue_model` | 需要 L3 数据 |
