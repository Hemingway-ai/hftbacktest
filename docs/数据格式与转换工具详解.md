# 数据格式与转换工具详解

## 一、概述

HftBacktest 使用 **NPZ 格式**（NumPy 压缩二进制）作为标准数据格式。本文档详解数据格式规范、各交易所的转换工具，以及数据验证方法。

---

## 二、核心数据格式

### 2.1 Event 数据格式 (event_dtype)

所有市场数据统一表示为 Event 数组：

```python
event_dtype = np.dtype([
    ('ev', 'u1'),           # 事件类型标志 (位组合)
    ('exch_ts', 'i8'),      # 交易所时间戳 (纳秒)
    ('local_ts', 'i8'),     # 本地时间戳 (纳秒)
    ('px', 'f8'),           # 价格
    ('qty', 'f8'),          # 数量
    ('order_id', 'u8'),     # 订单 ID
    ('ival', 'i8'),         # 整数值 (tick 价格等)
    ('fval', 'f8'),         # 浮点值
])
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ev` | uint8 | 事件类型位标志，见下表 |
| `exch_ts` | int64 | 交易所时间戳，纳秒精度 |
| `local_ts` | int64 | 本地接收时间戳，纳秒精度 |
| `px` | float64 | 价格 |
| `qty` | float64 | 数量 (正数) |
| `order_id` | uint64 | 订单 ID (L3 使用) |
| `ival` | int64 | 整数值，通常存储 tick 价格 |
| `fval` | float64 | 浮点值 |

### 2.2 事件类型标志

```python
# 位置标志
LOCAL_EVENT = 0b0000_0001   # 本地端事件
EXCH_EVENT  = 0b0000_0010   # 交易所端事件

# 数据类型
DEPTH_EVENT       = 0b0000_0100  # 深度更新
TRADE_EVENT       = 0b0000_1000  # 成交事件
DEPTH_CLEAR_EVENT = 0b0001_0000  # 深度清空
DEPTH_SNAPSHOT_EVENT = 0b0010_0000  # 深度快照
DEPTH_BBO_EVENT   = 0b0100_0000  # BBO 更新

# 方向
BUY_EVENT  = 0b0000_0001  # 买方
SELL_EVENT = 0b0000_0010  # 卖方

# 常用组合
LOCAL_BID_DEPTH_EVENT = LOCAL_EVENT | DEPTH_EVENT | BUY_EVENT   # 0b00000101
LOCAL_ASK_DEPTH_EVENT = LOCAL_EVENT | DEPTH_EVENT | SELL_EVENT  # 0b00000110
LOCAL_BID_TRADE_EVENT = LOCAL_EVENT | TRADE_EVENT | BUY_EVENT
LOCAL_ASK_TRADE_EVENT = LOCAL_EVENT | TRADE_EVENT | SELL_EVENT
```

### 2.3 延迟数据格式

订单延迟数据用于 `IntpOrderLatency` 模型：

```python
latency_dtype = np.dtype([
    ('req_ts', 'i8'),     # 请求时间戳 (策略提交订单)
    ('exch_ts', 'i8'),    # 交易所接收时间戳
    ('resp_ts', 'i8'),    # 响应时间戳 (策略收到确认)
])
```

**延迟计算**：
```
entry_latency = exch_ts - req_ts    # 订单提交延迟
resp_latency  = resp_ts - exch_ts   # 订单响应延迟
total_latency = resp_ts - req_ts    # 总延迟
```

## 三、NPZ 文件格式

### 3.1 文件结构

NPZ 文件是 NumPy 的压缩归档格式，包含一个或多个数组：

```python
# 保存
np.savez_compressed('data.npz', data=event_array)

# 加载
loaded = np.load('data.npz')
events = loaded['data']  # 通过 key 访问
```

### 3.2 标准命名约定

| 文件类型 | 命名格式 | 示例 |
|----------|----------|------|
| 行情数据 | `{symbol}_{date}.npz` | `ethusdc_20260302.npz` |
| 初始快照 | `{symbol}_{date}_eod.npz` | `ethusdc_20260301_eod.npz` |
| 延迟数据 | `feed_latency_{symbol}_{date}.npz` | `feed_latency_ethusdc_20260302.npz` |
| 订单延迟 | `order_latency_{symbol}_{date}.npz` | `order_latency_ethusdc_20260302.npz` |

### 3.3 数据内容

每个 NPZ 文件的 `data` 数组包含按时间戳排序的 Event 记录：

```
时间轴:
t0 ──► t1 ──► t2 ──► t3 ──► ...
│      │      │      │
▼      ▼      ▼      ▼
Event  Event  Event  Event
(深度)  (成交)  (深度)  (成交)
```

## 六、数据验证

### 6.1 验证工具

```python
from hftbacktest.data.validation import validate

# 验证 NPZ 数据文件
result = validate('btcusdt_20260302.npz')

if result.is_valid:
    print("数据验证通过")

| 检查项 | 说明 |
|--------|------|
| 时间戳单调性 | 确保时间戳严格递增 |

## 七、数据准备流水线

### 7.1 标准流程

```
1. 配置交易对列表
   └── tickers.json
       ↓
2. 下载原始数据
   └── collector 或第三方数据源
       ↓

   └── hftbacktest.data.utils.*

   └── feed_order_latency.py
       ↓

## 九、常见问题

### Q1: 时间戳单位是什么？

所有时间戳使用**纳秒**精度。转换关系：
```
1 秒 = 1,000,000,000 纳秒
1 毫秒 = 1,000,000 纳秒
1 微秒 = 1,000 纳秒
```

### Q2: 如何处理不同交易所的时间戳？

各交易所的时间戳格式可能不同，转换工具会统一转换为纳秒级 Unix 时间戳。

### Q3: NPZ 文件太大怎么办？

- 确保使用 `np.savez_compressed` 压缩
- 考虑按日期分割数据文件
- 使用 `parallel_load(True)` 并行加载

### Q4: 如何自定义数据格式？

需要确保数据符合 `event_dtype` 格式，并使用正确的事件类型标志。
