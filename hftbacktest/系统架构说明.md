# hftbacktest 子目录系统架构说明

> 参考根目录《系统架构分析.md》整理，范围仅覆盖 `hftbacktest/` 子目录。

## 1. 范围与目标

- 范围：`hftbacktest/` 目录下全部源码与示例文件。
- 目标：给出逐文件目录树说明，并总结该子项目的整体架构与运行链路。

## 2. 整体架构说明

### 2.1 模块分层

1. **入口与公共类型层**
- `src/lib.rs`：crate 入口，按 feature 暴露 `backtest`/`live`/`depth`。
- `src/types.rs`：事件、订单、状态、Bot/Recorder trait 与常量位标志。
- `src/prelude.rs`：统一 re-export，简化示例与业务代码导入。

2. **回测引擎层（`src/backtest/`）**
- `backtest/mod.rs` 提供 `L2AssetBuilder/L3AssetBuilder/BacktestBuilder`，负责组装“数据源 + 延迟模型 + 资产模型 + 手续费模型 + 深度实现 + 交易所处理器”。
- `proc/*` 将订单与行情事件分别在本地侧（Local）与交易所侧（Exchange）推进。
- `evs.rs` 用 `EventSet` 在多资产下做最早时间戳调度。
- `order.rs` 用双向 `OrderBus` + `LatencyModel` 模拟请求/回报时延。

3. **市场深度层（`src/depth/`）**
- 统一 trait：`MarketDepth/L2MarketDepth/L3MarketDepth/ApplySnapshot`。
- 多实现：`HashMap/BTree/ROI Vector/FusedHashMap`，在精度、鲁棒性、性能上做取舍。

4. **实盘运行层（`src/live/`）**
- `live/bot.rs` 提供 `LiveBotBuilder` 与 `LiveBot`，复用 `Bot` trait 交易逻辑。
- `live/ipc/*` 抽象通道与 Iceoryx IPC 实现，承载 connector 与 bot 的双向消息。
- `live/recorder.rs` 输出实盘状态日志。

5. **示例与流程编排层（`examples/`）**
- Python 脚本串联“选币 -> 下载 -> 转换 -> 延迟构造 -> 批量回测/网格搜索”。
- Rust 示例展示回测、实盘、错误处理与自定义事件处理扩展点。

### 2.2 关键运行链路

1. **回测链路**
- `DataSource`（文件/内存） -> `Reader` 分片读取与预处理 -> `EventSet` 选择下一事件 -> `Local/Exchange Processor` 推进订单状态与账户状态 -> `Recorder` 导出结果。

2. **实盘链路**
- Connector 推送 `LiveEvent` -> `Channel` 传输 -> `LiveBot` 更新订单/持仓/深度并触发策略逻辑 -> `LiveRequest` 回写至 connector 执行。

3. **统一策略接口**
- 回测与实盘都依赖 `types.rs` 中的 `Bot` trait，使同一策略函数（如 `examples/algo.rs::gridtrading`）可复用。

## 3. 文件说明目录树（逐文件）

```text
hftbacktest/
├── Cargo.toml                                   # Rust crate 元数据、feature 开关与依赖
├── README.md                                    # Rust 版本使用说明与示例入口
├── examples/
│   ├── 1_ticker.py                              # 拉取 Binance 合约 ticker 并生成交易对配置
│   ├── 2_download_tardis.py                     # 从 Tardis 批量下载 L2/trade 历史数据
│   ├── 3_convert.py                             # 将 Tardis CSV 转换为 Rust 回测用 NPZ
│   ├── 4_latency.py                             # 基于 feed 延迟生成订单延迟样本
│   ├── 5_backtest.py                            # 并行调用 Rust 回测程序做批量回测
│   ├── 6_gridsearch.py                          # 参数网格搜索并并行回测
│   ├── algo.rs                                  # 可复用网格策略核心逻辑（Bot trait 驱动）
│   ├── custom_evhandling.rs                     # 自定义 LocalProcessor 事件处理示例
│   ├── gridtrading.ipynb                        # 高频网格完整流程教程（数据到回测）
│   ├── gridtrading_256assets.ipynb              # 多资产（256）回测与筛选分析示例
│   ├── gridtrading_backtest.rs                  # 固定参数 Rust 回测入口
│   ├── gridtrading_backtest_args.rs             # CLI 参数化 Rust 回测入口
│   ├── gridtrading_live.rs                      # 连接实盘通道的网格策略示例（Binance）
│   ├── gridtrading_live_bybit.rs                # Bybit 实盘网格示例与错误回调处理
│   ├── live_order_error_handling.rs             # 实盘订单错误分级处理示例
│   ├── logging_order_latency.rs                 # 实盘订单回报延迟日志示例
│   ├── tickers.json                             # 示例交易对配置（约 49 个交易对）
│   └── tickers_256.json                         # 多资产实验交易对配置（256 个交易对）
└── src/
    ├── lib.rs                                   # crate 入口；按 feature 暴露核心模块
    ├── prelude.rs                               # 公共导出集合（depth/types/utils）
    ├── types.rs                                 # 核心类型、事件位标志、Bot/Recorder 等接口
    ├── utils/
    │   ├── aligned.rs                           # cache line 对齐数组（性能相关内存工具）
    │   └── mod.rs                               # 工具模块导出与价格精度计算
    ├── depth/
    │   ├── mod.rs                               # 市场深度 trait 与公共类型定义
    │   ├── btreemarketdepth.rs                  # BTreeMap 深度实现（有序结构）
    │   ├── hashmapmarketdepth.rs                # HashMap 深度实现（对缺失 feed 更鲁棒）
    │   ├── roivectormarketdepth.rs              # ROI 区间向量化深度实现（性能优化）
    │   └── fuse.rs                              # 多源深度融合实现（含时间戳去旧逻辑）
    ├── live/
    │   ├── mod.rs                               # 实盘模块导出与 Instrument 定义
    │   ├── bot.rs                               # LiveBot 构建、事件循环与下单接口
    │   ├── recorder.rs                          # 实盘状态日志记录器
    │   └── ipc/
    │       ├── mod.rs                           # IPC 抽象通道 trait
    │       ├── config.rs                        # IPC 配置加载与默认参数
    │       └── iceoryx.rs                       # Iceoryx 通道实现（收发/编解码）
    └── backtest/
        ├── mod.rs                               # 回测核心编排（Asset/Builder/Backtest）
        ├── assettype.rs                         # 资产计价模型（Linear/Inverse）
        ├── evs.rs                               # 多资产事件调度结构 EventSet
        ├── order.rs                             # 本地与交易所双向订单总线（含时延注入）
        ├── state.rs                             # 账户状态与成交后资产更新逻辑
        ├── recorder.rs                          # 回测结果记录与 CSV/NPZ 导出
        ├── data/
        │   ├── mod.rs                           # Data/DataPtr 与 NPY 读写导出
        │   ├── reader.rs                        # Reader/Cache/预处理与并行加载
        │   └── npy/
        │       ├── mod.rs                       # NPY/NPZ 头解析、读写主逻辑（含 S3 feature）
        │       └── parser.rs                    # NPY header 字典解析器（nom）
        ├── models/
        │   ├── mod.rs                           # 模型总入口与 re-export
        │   ├── fee.rs                           # 手续费模型（按金额/数量/固定费用）
        │   ├── latency.rs                       # 延迟模型（常量/插值历史延迟）
        │   └── queue.rs                         # 队列位置与成交概率模型（L2/L3）
        └── proc/
            ├── mod.rs                           # Processor/LocalProcessor trait 与导出
            ├── local.rs                         # L2 本地处理器（下单、状态同步、延迟记录）
            ├── nopartialfillexchange.rs         # L2 交易所处理器（仅全成）
            ├── partialfillexchange.rs           # L2 交易所处理器（支持部分成交）
            ├── l3_local.rs                      # L3 本地处理器（MBO）
            └── l3_nopartialfillexchange.rs      # L3 交易所处理器（仅全成）
```

## 4. 备注

- 本文档是面向 `hftbacktest/` 子目录的工程视图，不覆盖仓库其他子项目（`py-hftbacktest/`、`collector/`、`connector/`）。
- 若后续新增文件，建议按本目录树格式补齐一行说明，保证“文件-职责”映射持续可维护。
