# 实盘交易架构与流程详解

## 一、概述

HftBacktest 的实盘交易采用 **Bot + Connector** 分离架构，通过零拷贝 IPC 通信。核心优势：**回测和实盘使用同一套策略代码**。

---

## 二、架构设计

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        实盘交易系统                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────────┐    iceoryx2 IPC     ┌──────────────────┐     │
│  │   LiveBot    │ ◄──────────────────► │    Connector     │     │
│  │  (策略进程)   │   (零拷贝共享内存)    │  (交易所连接进程) │     │
│  │              │                      │                  │     │
│  │  - 运行策略   │    LiveEvent ──►     │  - WebSocket     │     │
│  │  - 管理订单   │    ◄── LiveRequest   │  - REST API      │     │
│  │  - 维护深度   │                      │  - 订单管理      │     │
│  └──────────────┘                      └──────────────────┘     │
│         │                                      │                 │
│         │ 策略代码 (与回测相同)                   │                 │
│         ▼                                      ▼                 │
│  ┌──────────────┐                      ┌──────────────────┐     │
│  │ Bot<MD> trait│                      │    交易所        │     │
│  │  (统一接口)   │                      │  Binance/Bybit   │     │
│  └──────────────┘                      └──────────────────┘     │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 核心组件

| 组件 | 进程 | 职责 |
|------|------|------|
| **LiveBot** | 策略进程 | 运行交易策略，管理订单和持仓 |
| **Connector** | 连接进程 | 与交易所通信，转发数据和订单 |
| **iceoryx2** | 系统级 | 提供零拷贝共享内存 IPC |

### 2.3 数据流

```
市场数据流 (交易所 → 策略):
交易所 WebSocket → Connector → iceoryx2 → LiveBot → 策略代码

订单流 (策略 → 交易所):
策略代码 → LiveBot → iceoryx2 → Connector → 交易所 REST API
```

## 三、Connector 详解

### 3.1 支持的交易所

| 交易所 | Feature Flag | 数据类型 |
|--------|-------------|----------|
| Binance USDⓈ-M Futures | `binancefutures` | 行情 + 交易 |
| Binance Spot | `binancespot` | 行情 + 交易 |
| Bybit | `bybit` | 行情 + 交易 |

### 3.2 Connector 内部结构

```
Connector
├── WebSocket 管理
│   ├── market_data_stream (行情数据)
│   └── user_data_stream (账户数据)
├── REST API 客户端
│   ├── 订单提交
│   ├── 订单取消
│   └── 账户查询
├── 订单管理器
│   ├── 订单状态跟踪
│   └── 订单 ID 映射
└── IPC 通道
    ├── 事件发送 (LiveEvent)
    └── 请求接收 (LiveRequest)
```

### 3.3 配置文件

Connector 使用 TOML 配置文件：

```toml
[connector]
exchange = "binancefutures"

[connector.binancefutures]
api_key = "your_api_key"
api_secret = "your_api_secret"

[connector.ipc]
# iceoryx2 配置
service_name = "hftbacktest"
```

### 3.4 构建与运行

```bash
# 构建所有连接器
cargo build -p connector --release

# 仅构建 Binance Futures
cargo build -p connector --release \
    --no-default-features \
    --features binancefutures

# 运行
./target/release/connector --config config.toml
```

## 四、LiveBot 详解

### 4.1 LiveBot 结构

```rust
pub struct LiveBot<MD: MarketDepth> {
    instruments: Vec<Instrument<MD>>,  // 合约列表
    ipc: IpcChannel,                   // IPC 通道
}
```

### 4.2 Instrument 结构

```rust
pub struct Instrument<MD: MarketDepth> {
    depth: MD,              // 市场深度
    state: State,           // 交易状态
    orders: OrderDict,      // 订单字典
    last_trades: Vec<Event>, // 最近成交
}
```

### 4.3 LiveBot 与 Backtest 的统一接口

两者都实现 `Bot<MD>` trait：

```rust
impl<MD: MarketDepth> Bot<MD> for LiveBot<MD> {
    fn elapse(&mut self, duration: i64) -> i64 { /* ... */ }
    fn depth(&self, asset_no: usize) -> &MD { /* ... */ }
    fn position(&self, asset_no: usize) -> f64 { /* ... */ }
    fn submit_buy_order(&mut self, ...) -> i64 { /* ... */ }
    // ... 其他方法
}

impl<MD: MarketDepth> Bot<MD> for Backtest<MD> {
    // 相同的接口实现
}
```

**这就是为什么策略代码可以无修改在回测和实盘中运行。**

## 五、IPC 通信详解

### 5.1 iceoryx2 简介

iceoryx2 是一个零拷贝的进程间通信框架：
- 基于共享内存
- 无序列化/反序列化开销
- 微秒级延迟
- 支持发布/订阅模式

### 5.2 通信消息类型

#### LiveEvent (交易所 → Bot)

```rust
pub enum LiveEvent {
    Feed {
        asset_no: usize,
        events: Vec<Event>,
    },
    Order {
        asset_no: usize,
        order: Order,
    },
    Position {
        asset_no: usize,
        position: f64,
    },
    Error {
        asset_no: usize,
        error: String,
    },
}
```

#### LiveRequest (Bot → 交易所)

```rust
pub enum LiveRequest {
    Order {
        asset_no: usize,
        order: Order,
    },
    RegisterInstrument {
        symbol: String,
        tick_size: f64,
        lot_size: f64,
    },
}
```

## 六、实盘部署流程

### 6.1 准备工作

1. **获取 API 密钥**
   - 在交易所创建 API Key
   - 设置适当的权限 (交易 + 读取)
   - 配置 IP 白名单

2. **收集延迟数据**
   - 参考 [订单延迟数据收集说明](订单延迟数据收集说明.md)
   - 至少收集 1-2 周的数据

3. **准备配置文件**

### 6.2 部署步骤

#### 步骤 1: 构建

```bash
# 构建 Connector
cargo build -p connector --release --features binancefutures

# 构建策略示例
cargo build --release --example gridtrading_live
```

#### 步骤 2: 配置 Connector

```toml
# config.toml
[connector]
exchange = "binancefutures"

[connector.binancefutures]
api_key = "YOUR_API_KEY"
api_secret = "YOUR_API_SECRET"

[connector.ipc]
service_name = "hftbacktest_btcusdt"
```

#### 步骤 3: 启动 Connector

```bash
./target/release/connector --config config.toml
```

#### 步骤 4: 运行策略

```bash
./target/release/examples/gridtrading_live
```

### 6.3 监控

- 监控 Connector 日志
- 监控策略输出
- 设置告警 (异常延迟、大额亏损等)

## 八、回测到实盘的迁移

### 8.1 代码层面

策略代码无需修改，只需更改 Bot 的构建方式：

```rust
// 回测
let hbt = Backtest::builder()
    .add_asset(asset)
    .build()?;

// 实盘
let hbt = LiveBot::builder()
    .add_instrument(instrument)
    .build()?;
```

### 8.2 配置层面

| 配置项 | 回测 | 实盘 |
|--------|------|------|
| 数据源 | NPZ 文件 | WebSocket |
| 延迟 | 模拟延迟 | 真实延迟 |
| 订单 | 模拟撮合 | 交易所撮合 |
| 资金 | 虚拟资金 | 真实资金 |

### 8.3 注意事项

1. **先用小资金测试**
2. **监控延迟指标**
3. **设置止损机制**
4. **检查手续费设置**
5. **验证订单类型支持**

## 九、常见问题

### Q1: Python 支持实盘吗？

目前实盘功能仅支持 Rust。Python 绑定的实盘功能正在开发中。

### Q2: 可以同时运行多个策略吗？

可以。每个 LiveBot 连接到一个 Connector，多个 Bot 可以共享同一个 Connector。

### Q3: 如何处理网络断连？

Connector 会自动重连 WebSocket。策略端会收到错误事件，需要在策略中处理。

### Q4: 订单延迟如何监控？

使用 `logging_order_latency.rs` 示例记录延迟数据，或在策略中调用 `order_latency()` 方法。

### Q5: 如何回滚到回测模式？

只需将 `LiveBot` 替换为 `Backtest`，策略代码不变。
