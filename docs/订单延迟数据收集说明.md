# 订单延迟数据收集说明

## 1. 概述

在高频交易回测中，延迟建模是影响回测结果真实性的关键因素。HftBacktest 框架围绕订单延迟提供了完整的 **数据收集 → 数据处理 → 回测加载** 流程。

本文档说明项目中订单延迟数据的核心数据结构、收集方式、合成方法，以及在回测中如何使用。

---

## 2. 延迟类型

框架识别三种延迟：

```
交易所                          本地
  │                              │
  │──── Feed 延迟 ──────────────▶│  (行情从交易所到本地)
  │                              │
  │◀──── Order Entry 延迟 ──────│  (订单从本地到交易所)
  │                              │
  │──── Order Response 延迟 ───▶│  (响应从交易所到本地)
```

| 延迟类型 | 定义 | 计算方式 |
|---------|------|---------|
| Feed 延迟 | 交易所发送行情到本地接收的时间差 | `local_ts - exch_ts` |
| Order Entry 延迟 | 本地发出订单到交易所处理的时间差 | `exch_ts - req_ts` |
| Order Response 延迟 | 交易所处理完成到本地收到响应的时间差 | `resp_ts - exch_ts` |

## 3. 核心数据结构

### 3.1 Rust 定义

**文件**: `hftbacktest/src/backtest/models/latency.rs`

```rust
#[repr(C, align(32))]
pub struct OrderLatencyRow {
    pub req_ts: i64,    // 本地发出请求的时间戳 (纳秒)
    pub exch_ts: i64,   // 交易所处理请求的时间戳 (纳秒)
    pub resp_ts: i64,   // 本地收到响应的时间戳 (纳秒)
    pub _padding: i64,  // 32 字节对齐填充
}
```

### 3.2 Python / NumPy dtype

**文件**: `py-hftbacktest/hftbacktest/data/utils/feed_order_latency.py`

```python
order_latency_dtype = np.dtype([
    ('req_ts', 'i8'),
    ('exch_ts', 'i8'),

```

> 所有时间戳均使用 **纳秒精度**，与实盘 LiveBot 保持一致。

## 4. 真实订单延迟的收集方式

### 4.1 方式一：实盘交易记录 (Rust)

**文件**: `hftbacktest/examples/logging_order_latency.rs`

通过 `order_recv_hook` 在实盘中拦截每笔订单响应，记录三个时间戳：

```rust
LiveBot::builder()
    .register("binancefutures", "SOLUSDT", 0.001, 1.0)
    .order_recv_hook(|req, resp| {
        if (req.req == Status::New || req.req == Status::Canceled)
            && (resp.req == Status::None)
        {
            info!(
                req_timestamp = req.local_timestamp,       // 本地发出请求的时间
                exch_timestamp = resp.exch_timestamp,      // 交易所处理的时间
                resp_timestamp = Utc::now()                // 本地收到响应的时间
                    .timestamp_nanos_opt().unwrap(),
                req = ?req.req,
                "Order response is received."
            );
        }
        Ok(())
    })
    .build()
    .unwrap();
```

**采集逻辑**：
1. 每当收到订单响应时触发 hook
2. `req.local_timestamp` → 本地发出订单的时间
3. `resp.exch_timestamp` → 交易所处理订单的时间
4. `Utc::now()` → 本地当前时间（即收到响应的时间）
5. 通过 `tracing` 日志输出，后续可从日志文件中解析

### 4.2 方式二：周期性测试订单

文档推荐的安全做法（不产生实际成交）：

1. **定期提交不可能成交的限价订单**（价格大幅偏离市场价）
2. **立即取消该订单**
3. 记录提交和取消过程中的三个时间戳

这种方式的优点：
- 不需要实际交易，不承担市场风险
- 能获取真实的网络延迟数据
- 可以高频采集，数据更密集

## 5. 合成订单延迟（无真实数据时）

当没有真实订单延迟数据时，可以基于 **Feed 延迟** 人工合成。

### 5.1 核心公式

```
order_entry_latency = mul_entry × feed_latency + offset_entry
order_resp_latency  = mul_resp  × feed_latency + offset_resp
```

其中 `feed_latency = local_ts - exch_ts`（从行情数据中直接计算）。

### 5.2 默认参数

| 参数 | 典型值 | 含义 |
|------|--------|------|
| `mul_entry` | 4 | 订单入场延迟 ≈ 4 倍 Feed 延迟 |
| `mul_resp` | 3 | 订单响应延迟 ≈ 3 倍 Feed 延迟 |
| `offset_entry` | 0 | 入场延迟偏移量 |
| `offset_resp` | 0 | 响应延迟偏移量 |

### 5.3 数据处理流程

**文件**: `py-hftbacktest/hftbacktest/data/utils/feed_order_latency.py`

```
行情 .npz 文件
    │
    ▼
过滤有效事件 (同时包含 exch_ts 和 local_ts)
    │
    ▼
按 1 秒间隔重采样 (每天约 86,400 行)
    │
    ▼
计算 feed_latency，乘以系数生成 order_latency
    │
    ▼
保存为 .npz 文件 (np.savez_compressed)
```

### 5.4 Python 使用示例

```python
from hftbacktest.data.utils import generate_order_latency

# 从行情数据生成订单延迟
order_latency = generate_order_latency(
    feed_file='usdm/ethusdc_20260302.npz',
    output_file='usdm/feed_latency_ethusdc_20260302.npz',
    mul_entry=4,
    mul_resp=3
)
```

### 5.5 批量生成（多天数据）

**文件**: `hftbacktest/examples/4_latency.py`

```python
from datetime import datetime, timedelta

date = datetime.strptime('20240501', '%Y%m%d')
date_to = datetime.strptime('20240531', '%Y%m%d')

while date <= date_to:
    yyyymmdd = date.strftime('%Y%m%d')
    generate_order_latency(
        f'{symbol}_{yyyymmdd}.npz',
        output_file=f'latency_{yyyymmdd}.npz',
        mul_entry=4,
        mul_resp=3
    )
    date += timedelta(days=1)
```

## 6. 回测中的延迟模型

### 6.1 ConstantLatency（固定延迟）

最简单的模型，使用固定值：

```python
# Python
asset.constant_latency(
    entry_latency=10_000_000,     # 10ms 入场延迟
    response_latency=10_000_000   # 10ms 响应延迟
)
```

```rust
// Rust
ConstantLatency::new(10_000_000, 10_000_000)
```

### 6.2 IntpOrderLatency（插值延迟，推荐）

基于真实/合成延迟数据，在数据点之间做线性插值：

```python
# Python
asset.intp_order_latency(
    data='latency_20240501.npz',
    latency_offset=0
)
```

```rust
// Rust
IntpOrderLatency::new(
    vec![DataSource::File("latency_20240501.npz".to_string())],
    0  // latency_offset
)
```

**插值逻辑**：
- 给定任意时间戳 `t`，找到相邻的两个数据点 `(t1, lat1)` 和 `(t2, lat2)`
- 线性插值计算: `lat = lat1 + (lat2 - lat1) / (t2 - t1) × (t - t1)`

**异常处理**：
- 当 `exch_ts ≤ 0` 时表示交易所拒绝了订单（如过载/技术问题）
- 此时返回负延迟值，表示被拒绝，值为本地收到拒绝通知的延迟

### 6.3 自定义延迟模型

实现 `LatencyModel` trait 即可：

```rust
pub trait LatencyModel {
    fn entry(&mut self, timestamp: i64, order: &Order) -> i64;
    fn response(&mut self, timestamp: i64, order: &Order) -> i64;
}
```
