# 机器学习订单过滤接入指南

> 在 OBI 做市策略基础上，加入**逻辑回归 (Logistic Regression) 模型**作为"交易前过滤器"：
> 每次下单前先用模型预测这笔单是 **好交易** 还是 **坏交易**，预测概率低于阈值（例如 `0.60`）则**取消该侧报价**。

本文档提供从**数据生成 → 特征工程 → 标签构造 → 模型训练 → 系数导出 → 策略接入 → 阈值校准**的完整闭环方案，所有代码可直接复制运行。

---

## 一、整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│  阶段 1：训练（离线，运行一次）                                    │
│                                                                 │
│  现有回测 fills/snapshots  ──►  特征矩阵 X                       │
│                              ──►  标签向量 y (好/坏交易)           │
│                              ──►  sklearn LogisticRegression     │
│                              ──►  coef_ + intercept_  导出 .npz  │
└─────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│  阶段 2：推理（回测 / 实盘主循环内）                                │
│                                                                 │
│  每个 tick：                                                     │
│    1. 计算 OBI alpha（已有逻辑）                                  │
│    2. 构造特征向量 x                                             │
│    3. z   = w · x + b       (njit 内联)                         │
│       p   = sigmoid(z)                                          │
│    4. if p < threshold:                                         │
│           跳过该侧下单  ← 关键过滤点                              │
│       else:                                                     │
│           正常挂单（原逻辑）                                      │
└─────────────────────────────────────────────────────────────────┘
```

### 为什么用逻辑回归？

| 方案 | 优点 | 缺点 |
|------|------|------|
| **逻辑回归 (推荐)** | 系数可导出为常数数组，njit 内联计算只需加法+乘法+1 次 exp；可解释性强 | 仅线性决策边界 |
| 树模型 (XGBoost/LGBM) | 精度高 | 无法在 njit 中直接调用，需要导出为 if-else 或改用 Python 循环（牺牲性能） |
| 神经网络 | 可拟合复杂模式 | 需在 njit 中手写前向传播，维护成本高 |

对于做市策略这种**每个 tick 都要推理**的高频场景，逻辑回归的 **微秒级内联推理** 是决定性优势。

---

## 二、核心概念：什么是"好交易 / 坏交易"

做市策略最大的敌人是**逆向选择 (Adverse Selection)**：你的限价单成交了，但成交后价格立刻朝不利方向运动——你被"毒性订单流"击中了。

### 2.1 用 Forward Return 定义标签

假设时刻 `t` 一笔买单在价格 `P_fill` 成交，观察 `H` 秒后的 mid price `P_{t+H}`：

- **买单**：
  - 好交易 (y=1)：`P_{t+H} - P_fill > cost`  （价格上涨覆盖成本）
  - 坏交易 (y=0)：`P_{t+H} - P_fill ≤ cost`  （价格没涨或下跌，被套）

- **卖单**：
  - 好交易 (y=1)：`P_fill - P_{t+H} > cost`
  - 坏交易 (y=0)：`P_fill - P_{t+H} ≤ cost`

其中 `cost` 是手续费 + 半个 spread，确保"好交易"是真正盈利而不是仅覆盖成本。

### 2.2 为什么不用 PnL 余额变化？

`fills` 里的 `balance_after` 包含了**未平仓浮亏**和**手续费**，与单笔交易好坏混淆。Forward return 更纯粹地衡量"这一笔是否被市场带偏"，与 ML 过滤的目标完全一致。

### 2.3 预测窗口 H 的选择

| H | 含义 | 适用场景 |
|---|------|----------|
| 1~5 秒 | 捕捉瞬时毒性流 | 超高频、tick 级策略 |
| **10~60 秒** | 平衡噪声与信号 | **推荐，OBI 做市常用** |
| 5~30 分钟 | 捕捉中期趋势 | 低频做市 |

建议同时训练多个 H 的模型做对比，选回测 Sharpe 最高的。

## 三、步骤 1：生成训练数据

你的 `obi_detailed_strategy.py` 已经导出了 `obi_detailed_output.json`，其中包含 `fills` 和 `snapshots` 两个数组——**这就是天然的训练数据源**。

> 推荐做法：在**多天数据**上跑回测（例如 5~10 个交易日），把每天的 `obi_detailed_output_YYYYMMDD.json` 都保存下来，训练时合并，样本更充分。

每个 fill 记录的字段（来自 `fill_dtype`）：

```json
{
  "ts": 1709337600000000000,   // 成交时间 (ns)
  "side": 1,                    // 1=BUY, -1=SELL
  "ep": 3245.6,                 // 成交价
  "op": 3245.5,                 // 挂单价
  "mid": 3245.65,               // 成交时刻 mid
  "spr": 0.2,                   // 成交时刻 spread
  "alpha": 1.23,                // 成交时刻标准化 OBI
  "pos": 12.5,                  // 成交后持仓
  ...
}
```

每个 snapshot 记录了**每个 tick** 的全量特征，是构造滚动特征（动量、波动率）的数据源。

## 四、步骤 2：特征工程

### 4.1 特征清单

| 类别 | 特征 | 说明 | 数据来源 |
|------|------|------|----------|
| **OBI** | `alpha` | 标准化订单簿失衡 | fill / snapshot |
| | `imbalance_raw` | 原始买卖盘差 | fill |
| | `alpha_slope_5s` | alpha 近 5 秒变化率 | snapshot 滚动 |
| **微观结构** | `spread` | best_ask - best_bid | fill |
| | `spread_norm` | spread / mid | 派生 |
| **仓位** | `position_norm` | position / order_qty | fill |
| | `inventory_skew` | 持仓偏多/偏空标志 | 派生 |
| **动量** | `ret_1s`, `ret_5s`, `ret_30s` | mid 近 N 秒收益率 | snapshot 滚动 |
| **波动率** | `vol_30s` | mid 近 30 秒已实现波动 | snapshot 滚动 |
| **成交** | `seconds_since_last_fill` | 距上次成交秒数 | fill |
| | `trade_intensity_30s` | 近 30 秒成交次数 | kline / fill |

### 4.2 关键原则：**特征必须可在推理时刻计算**

策略主循环里我们只能拿到当前 tick 及之前的数据。所以训练特征**绝不能**用到未来信息（例如"未来 10 秒成交量"）。所有滚动特征都用 `[t-window, t]` 区间。

### 4.3 特征标准化

逻辑回归对量纲敏感，必须做 Z-score 标准化：

```python
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler().fit(X_train)
X_train = scaler.transform(X_train)
```

**标准化参数 (`mean_`, `scale_`) 必须和模型系数一起导出**，否则推理结果错误。这是最容易踩的坑，下文会专门处理。

## 五、步骤 3：标签生成

### 5.1 完整标签生成代码

新建文件 `examples/ml_obi_filter/train_label.py`：

```python
"""
从 obi_detailed_output.json 构造 ML 训练样本 (X, y)。
标签：成交后 HORIZON 秒的 forward return 是否有利可图。
"""
import json
import numpy as np
import pandas as pd

HORIZON_SEC = 30          # 前瞻窗口（秒），与推理目标一致
COST_BPS = 1.5            # 每笔综合成本（手续费+半spread），单位 bps
OUTPUT_NPZ = 'examples/ml_obi_filter/dataset.npz'


def build_samples(json_paths):
    """合并多个 json 文件，返回 (X, y, meta_df)。"""
    samples = []

    for path in json_paths:
        with open(path) as f:
            d = json.load(f)

        fills = pd.DataFrame(d['fills'])
        snaps = pd.DataFrame(d['snapshots'])

        # 时间统一为秒级浮点
        fills['t_sec']  = fills['ts']  / 1e9
        snaps['t_sec']  = snaps['ts']  / 1e9

        # 用 snapshot 序列构造 mid 的查找函数，方便按时刻取 forward mid
        snap_t   = snaps['t_sec'].values
        snap_mid = snaps['mid'].values

        def forward_mid(t_sec, horizon):
            """返回 t + horizon 时刻的 mid（线性插值）。"""
            target = t_sec + horizon
            if target > snap_t[-1]:
                return np.nan
            idx = np.searchsorted(snap_t, target)
            # 简单取最近，不用插值（秒级 snapshot 已足够细）
            return snap_mid[min(idx, len(snap_t) - 1)]

        for _, row in fills.iterrows():
            fill_px = row['ep']
            side    = row['side']                     # 1=BUY, -1=SELL
            mid_fwd = forward_mid(row['t_sec'], HORIZON_SEC)

            if np.isnan(mid_fwd):
                continue

            # 方向化 forward return
            signed_ret = side * (mid_fwd - fill_px) / fill_px * 1e4   # bps
            cost       = COST_BPS
            y          = int(signed_ret > cost)                       # 1=好交易, 0=坏交易

            # ===== 特征 =====
            # 用 fill 自带字段 + 从 snapshot 取最近一档补全
            feat = {
                'alpha':            row['alpha'],
                'imbalance':        row['imba'] if 'imba' in row else 0.0,
                'spread':           row['spr'],
                'spread_norm':      row['spr'] / row['mid'] if row['mid'] else 0.0,
                'position_norm':    row['pos'],
                'side':             side,
                # 成交价相对 mid 的偏移（限价单成交质量）
                'fill_offset_bps':  (row['ep'] - row['mid']) / row['mid'] * 1e4 * side,
            }
            feat['label']  = y
            feat['signed_ret_bps'] = signed_ret
            samples.append(feat)

    df = pd.DataFrame(samples)
    print(f'样本总数: {len(df)}, 好交易占比: {df.label.mean():.2%}')
    return df


if __name__ == '__main__':
    # 把每天生成的回测 json 都列在这里
    json_files = [
        'examples/obi_detailed_output.json',
        # 'examples/obi_detailed_output_20260303.json',
        # 'examples/obi_detailed_output_20260304.json',
    ]
    df = build_samples(json_files)
    df.to_csv('examples/ml_obi_filter/samples.csv', index=False)

    feature_cols = ['alpha', 'imbalance', 'spread', 'spread_norm',
                    'position_norm', 'side', 'fill_offset_bps']
    X = df[feature_cols].values.astype(np.float64)
    y = df['label'].values.astype(np.int64)

    np.savez(OUTPUT_NPZ, X=X, y=y, feature_cols=np.array(feature_cols))
    print(f'已保存 {OUTPUT_NPZ}')
```

运行后得到 `dataset.npz`，包含 `X` (N×k)、`y` (N,)。

## 六、步骤 4：模型训练与评估

新建 `examples/ml_obi_filter/train_model.py`：

```python
"""
训练逻辑回归模型，输出：
  - 模型评估报告 (precision / recall / AUC)
  - 系数文件 model.npz (供 njit 推理使用)
"""
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import TimeSeriesSplit
from sklearn.metrics import (classification_report, roc_auc_score,
                             precision_recall_curve)

DATA_NPZ  = 'examples/ml_obi_filter/dataset.npz'
MODEL_NPZ = 'examples/ml_obi_filter/model.npz'
THRESHOLD = 0.60          # 用户指定的阈值，下文会校准


def load_data():
    d = np.load(DATA_NPZ, allow_pickle=True)
    X, y = d['X'], d['y']
    feature_cols = list(d['feature_cols'])
    print(f'特征列: {feature_cols}')
    print(f'X shape: {X.shape}, 正样本率: {y.mean():.2%}')
    return X, y, feature_cols


def train():
    X, y, feature_cols = load_data()

    # === 1) 时序切分（高频数据绝不能随机切，避免未来泄漏）===
    tscv = TimeSeriesSplit(n_splits=5)
    split = list(tscv.split(X))[-1]      # 取最后一次 train/test
    tr_idx, te_idx = split
    X_tr, y_tr = X[tr_idx], y[tr_idx]
    X_te, y_te = X[te_idx], y[te_idx]

    # === 2) 标准化（仅在训练集上拟合）===
    scaler = StandardScaler().fit(X_tr)
    X_tr_s = scaler.transform(X_tr)
    X_te_s = scaler.transform(X_te)

    # === 3) 训练 ===
    # class_weight='balanced' 自动处理类别不平衡（坏交易往往较多）
    clf = LogisticRegression(
        class_weight='balanced',
        C=1.0,
        solver='lbfgs',
        max_iter=1000,
    )
    clf.fit(X_tr_s, y_tr)

    # === 4) 评估 ===
    p_te = clf.predict_proba(X_te_s)[:, 1]   # P(好交易)
    print('\n=== 默认阈值 (0.5) 评估 ===')
    print(classification_report(y_te, (p_te >= 0.5).astype(int),
                                target_names=['坏交易', '好交易']))
    try:
        auc = roc_auc_score(y_te, p_te)
        print(f'AUC = {auc:.4f}')
    except ValueError:
        auc = float('nan')

    # === 5) 阈值校准：找满足 precision 目标的最小阈值 ===
    prec, rec, thr = precision_recall_curve(y_te, p_te)
    # 业务目标：过滤后的单子中好交易占比高 (precision 高)
    # 在 precision >= 0.65 的阈值中选 recall 最大的
    target_prec = 0.65
    valid = np.where(prec[:-1] >= target_prec)[0]
    if len(valid):
        best_i = valid[np.argmax(rec[:-1][valid])]
        calib_thr = thr[best_i]
        print(f'\n校准阈值 (precision≥{target_prec}): {calib_thr:.3f}, '
              f'对应 precision={prec[best_i]:.3f}, recall={rec[best_i]:.3f}')
    else:
        calib_thr = THRESHOLD
        print(f'\n无法满足 precision≥{target_prec}，使用默认阈值 {THRESHOLD}')

    # === 6) 导出系数（关键！njit 推理用）===
    np.savez(
        MODEL_NPZ,
        coef=clf.coef_[0].astype(np.float64),         # shape (k,)
        intercept=np.array([clf.intercept_[0]], dtype=np.float64),
        mean=scaler.mean_.astype(np.float64),          # 标准化参数
        scale=scaler.scale_.astype(np.float64),
        threshold=np.array([calib_thr], dtype=np.float64),
        feature_cols=np.array(feature_cols),
    )
    print(f'\n已导出模型 → {MODEL_NPZ}')
    print(f'  coef      = {clf.coef_[0]}')
    print(f'  intercept = {clf.intercept_[0]}')
    print(f'  阈值       = {calib_thr:.3f}')

    # 特征重要性（|coef / scale|）
    imp = np.abs(clf.coef_[0] / scaler.scale_)
    for name, v in sorted(zip(feature_cols, imp), key=lambda x: -x[1]):
        print(f'  {name:20s} importance = {v:.4f}')


if __name__ == '__main__':
    train()
```

运行后会打印评估报告和特征重要性，并生成 `model.npz`。

> **关于用户提到的"阈值大于 60"**：本文档把 sigmoid 输出 `p` 解释为 **P(好交易)**，所以 `p >= 0.60` 才放行交易。如果你希望直接用 `0~100` 整数刻度，把 `threshold` 乘 100 即可，逻辑完全等价。

## 七、步骤 5：在 njit 策略中接入模型（核心）

这是**最关键的一步**。由于 `obi_mm_detailed` 被 `@njit` 装饰，**不能**在其中调用 sklearn。但逻辑回归的预测本质上只是：

$$p = \sigma(w \cdot x + b) = \frac{1}{1 + e^{-(w \cdot x + b)}}$$

我们把 `w, b, mean, scale` 全部作为数组参数传入，在 JIT 内手写计算即可。

### 7.1 新增 njit 推理函数

在 `obi_detailed_strategy.py` 的 `@njit` 区块内添加：

```python
@njit
def _sigmoid(z):
    """数值稳定的 sigmoid。"""
    if z >= 0.0:
        return 1.0 / (1.0 + np.exp(-z))
    else:
        e = np.exp(z)
        return e / (1.0 + e)


@njit
def _predict_good_proba(coef, intercept, mean, scale, features):
    """
    输入原始（未标准化）特征数组，输出 P(好交易)。
    内部完成标准化 + 线性组合 + sigmoid。
    """
    z = intercept[0]
    for i in range(len(coef)):
        x_std = (features[i] - mean[i]) / scale[i]
        z += coef[i] * x_std
    return _sigmoid(z)
```

## 八、步骤 6：阈值校准与 A/B 对比

### 8.1 阈值的业务含义

设 `p = P(好交易)`，阈值 `τ`：

| τ 取值 | 行为 | 结果 |
|--------|------|------|
| τ = 0 | 不过滤（始终下单） | = baseline，成交多但坏单多 |
| τ = 0.5 | 默认 | 平衡 |
| **τ = 0.60** | 用户要求 | 略保守，过滤明显坏单 |
| τ = 0.80 | 极保守 | 成交大幅减少，但单笔质量高 |

> **注意**：过滤会**减少成交次数**。如果模型不准，过度过滤反而降低 PnL。一定要用回测验证，不要拍脑袋调阈值。

### 8.2 网格搜索最优阈值

新建 `examples/ml_obi_filter/calibrate_threshold.py`：

```python
"""
对多个 threshold 跑回测，比较 Sharpe / PnL / 成交数。
"""
import subprocess, json, numpy as np

THRESHOLDS = [0.0, 0.5, 0.55, 0.60, 0.65, 0.70, 0.75, 0.80]

# 假设你已经把策略改成接受环境变量 ML_THRESHOLD
# 否则改成读取一个 thr.json 配置文件
results = []
for thr in THRESHOLDS:
    # 修改 model.npz 中的 threshold 字段
    m = np.load('examples/ml_obi_filter/model.npz', allow_pickle=True)
    np.savez('examples/ml_obi_filter/model.npz',
             coef=m['coef'], intercept=m['intercept'],
             mean=m['mean'], scale=m['scale'],
             threshold=np.array([thr], dtype=np.float64),
             feature_cols=m['feature_cols'])

    subprocess.run(['python', 'examples/obi_detailed_strategy.py'], check=True)

    # 读回结果，从 recorder_5m 算 Sharpe
    with open('examples/obi_detailed_output_ml.json') as f:
        d = json.load(f)
    eq = np.array([r['equity_wo_fee'] for r in d['recorder_5m']])
    rets = np.diff(eq) / eq[:-1]
    sharpe = (rets.mean() / rets.std() * np.sqrt(252 * 288)
              if rets.std() > 0 else 0)
    results.append((thr, eq[-1] - eq[0], len(d['fills']), sharpe))

print('\n=== 阈值扫描结果 ===')
print(f'{"threshold":>10} {"PnL":>12} {"fills":>8} {"Sharpe":>8}')
for thr, pnl, n, sh in results:
    print(f'{thr:>10.2f} {pnl:>12.2f} {n:>8d} {sh:>8.2f}')
```

选出 Sharpe 最高的阈值写回 `model.npz`。

## 十一、常见问题与最佳实践

### 11.1 njit 报错"Cannot infer type"

**原因**：传入的数组 dtype 不是 `float64`，或 `np.array([...])` 混合了 int/float。

**解决**：所有模型参数显式 `.astype(np.float64)`，特征数组用 `np.array([...], dtype=np.float64)`。

### 11.2 特征顺序错误导致预测全错

**关键**：训练时的 `feature_cols` 顺序必须与策略里构造 `feat_bid` 数组的顺序**完全一致**。建议在 `model.npz` 里存 `feature_cols`，策略加载时 assert 校验：

```python
expected = ['alpha', 'imbalance', 'spread', 'spread_norm',
            'position_norm', 'side', 'fill_offset_bps']
assert list(m['feature_cols']) == expected, '特征顺序不匹配！'
```

### 11.3 类别不平衡

做市策略中**坏交易通常占多数**（这是做市要解决的核心问题）。处理方式：
- `LogisticRegression(class_weight='balanced')` —— 已在示例代码中启用
- 或对坏交易过采样

### 11.4 时序切分，不可随机切

高频数据有强自相关性，随机 K-Fold 会造成**未来信息泄漏**，AUC 虚高。务必用 `TimeSeriesSplit`（示例代码已用）。

### 11.5 概率校准

逻辑回归的 sigmoid 输出在大样本下近似良好校准的概率，可直接当阈值用。如果发现"预测 0.7 但实际只有 0.55"，可加一层 isotonic regression：

```python
from sklearn.isotonic import IsotonicRegression
iso = IsotonicRegression().fit(p_train, y_train)
p_calibrated = iso.predict(p_test)
```

### 11.6 模型衰减与再训练

市场微观结构会变化，模型应**定期重训**（例如每周/每月用最近 N 天数据重训）。建议：
- 把每天 `obi_detailed_output_YYYYMMDD.json` 归档
- 重训时用最近 30 天数据
- 用最近 5 天做验证，监控 AUC 下降

### 11.7 不要用未来特征

绝对禁止的特征：未来 N 秒的成交量、未来成交价、未来持仓。所有滚动窗口只用 `[t-window, t]`。

### 11.8 实盘部署

实盘时把 `model.npz` 的系数硬编码或从配置加载，njit 推理逻辑与回测**完全相同**——这正是本方案的核心优势：**回测/实盘一致性**，不会因为换框架产生偏差。

## 十二、进阶方向

1. **非线性化**：对重要特征做分桶或加交互项（如 `alpha * spread_norm`），仍可保持线性模型形式。
2. **多模型集成**：分别训练买单/卖单模型（`side` 固定后特征空间更纯净）。
3. **滚动预测**：每个 tick 不只预测固定 H，而是同时预测 5s/30s/2min 多个 horizon，综合决策。
4. **升级为 GBDT**：若线性模型 AUC < 0.6，可改用 LightGBM，再用 `treelite` 或手写 if-else 导出到 njit（成本较高，仅当收益明显时再做）。
5. **在线学习**：每个交易日用昨天的 fills 增量更新系数（SGDClassifier.partial_fit），适应市场变化。

## 附录：完整 njit 推理函数参考实现

```python
from numba import njit
import numpy as np


@njit(cache=True)
def _sigmoid(z):
    if z >= 0.0:
        return 1.0 / (1.0 + np.exp(-z))
    else:
        e = np.exp(z)
        return e / (1.0 + e)


@njit(cache=True)
def predict_good_proba(coef, intercept, mean, scale, features):
    """
    Logistic Regression 推理（njit 内联版）。

    参数
    ----
    coef       : np.float64[k]   模型权重
    intercept  : np.float64[1]   截距
    mean       : np.float64[k]   StandardScaler.mean_
    scale      : np.float64[k]   StandardScaler.scale_
    features   : np.float64[k]   原始特征（顺序须与训练时一致）

    返回
    ----
    p : float   P(好交易)，范围 (0, 1)
    """
    z = intercept[0]
    for i in range(len(coef)):
        z += coef[i] * (features[i] - mean[i]) / scale[i]
    return _sigmoid(z)


# 使用示例
if __name__ == '__main__':
    m = np.load('examples/ml_obi_filter/model.npz', allow_pickle=True)
    coef, intercept = m['coef'], m['intercept']
    mean, scale     = m['mean'], m['scale']
    threshold       = m['threshold'][0]

    # 模拟一个 tick 的特征
    feat = np.array([1.2, 5.3, 0.2, 6.2e-5, 0.5, 1.0, 8.5], dtype=np.float64)

    p = predict_good_proba(coef, intercept, mean, scale, feat)
    print(f'P(好交易) = {p:.3f}, 阈值 = {threshold:.3f}')
    print('→ 放行' if p >= threshold else '→ 取消该侧下单')
```

---

**总结一句话**：训练时把 sklearn 的 `coef_ / intercept_ / mean_ / scale_` 导成 `.npz` 数组，推理时在 `@njit` 函数里手写 `z = w·(x-μ)/σ + b; p = sigmoid(z)`，下单前判断 `p >= threshold`。整个过程**零依赖、微秒级、回测实盘一致**。
